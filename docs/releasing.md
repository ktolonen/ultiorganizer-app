# Releasing

Builds run on EAS (`eas.json`), owned by the `ultiorganizer-team` Expo account. Run EAS CLI as `npx eas-cli`.

| Profile          | Output                                                           | Use                                         |
| ---------------- | ---------------------------------------------------------------- | ------------------------------------------- |
| `development`    | APK, development client                                          | daily development; allows `http` to the LAN |
| `preview`        | APK, internal distribution, `preview` update channel             | testers                                     |
| `production`     | AAB for Google Play, IPA for the App Store, `production` channel | store releases                              |
| `production-apk` | APK, internal distribution, `production` channel                 | the APK attached to GitHub releases         |

The app version (`version` in `app.config.ts`) is set by hand. The build numbers (Android version code, iOS build number) are kept on EAS (`appVersionSource: remote`) and increased by every `production` and `production-apk` build; the two Android profiles share one counter.

## Android APK on GitHub

1. Make sure CI passes on `main`.
2. Build: `npx eas-cli build --profile production-apk --platform android`.
3. Download the APK from the build page and name it `ultiorganizer-scorekeeper-<version>-<version code>.apk`.
4. Create a GitHub release tagged `v<version>` on the commit the build was made from, with the APK and its SHA-256 attached.

Users update by installing a newer APK over the old one. That works only when the version code is higher and the signing key is the same.

## Signing

The Android upload keystore was generated by EAS and is kept there. Every Android build is signed with it, so APKs install over each other. Download a backup with `npx eas-cli credentials`; losing it means users have to uninstall to update.

If the app is published on Google Play, Play App Signing re-signs it with Google's key. A Play install then can't update an APK installed from GitHub, or the other way round, without uninstalling first, which deletes the games on the phone, including entries not yet sent.

The first iOS build has to run interactively to sign in to the Apple Developer account and create the distribution certificate and provisioning profile: `npx eas-cli build --profile production --platform ios`. Later builds can run non-interactively.

## Over-the-air updates

`expo-updates` is configured with `runtimeVersion: { policy: 'appVersion' }`, so a build only takes updates published for its own app version. Publish a JavaScript-only fix with `npx eas-cli update --channel production`. A change to native code or config needs a new build and a new app version.
