# Development

The app is built with Expo and React Native in TypeScript, for Android and iOS. Its scorekeeping and timekeeping logic lives in pure modules with unit tests; see [architecture](architecture.md).

Not done yet on the development side: end-to-end tests on devices and contract tests against a live server.

## Setup

```sh
nvm use                      # Node 22 (.nvmrc)
npm ci                       # .npmrc sets legacy-peer-deps: openapi-typescript wants TypeScript 5, the SDK ships 6
npx expo start               # dev server
```

Camera, SQLite and notifications need a development build rather than Expo Go:

```sh
APP_VARIANT=development npx eas-cli build --profile development --platform android
```

The development build has its own bundle ID and name, so it installs next to a release build, and it accepts `http` to LAN addresses and the Android emulator (`10.0.2.2`) for a local server. Release builds accept only `https`.

Develop on the host. Jest, `tsc` and ESLint need only Node; emulators and simulators don't run well in containers, and native builds go through EAS. For a local server, use the dev stack in the server repository (`docs/dev/compose.yaml` in [ultiorganizer](https://github.com/ktolonen/ultiorganizer)).

`ios/` and `android/` are generated by prebuild and gitignored. Configure native behaviour in `app.config.ts` and config plugins, never by editing them. Add dependencies with `npx expo install`, which picks versions that match the SDK.

## Checks

CI (`.github/workflows/ci.yml`) runs all of these; run them before calling a change done.

```sh
npm run typecheck            # tsc --noEmit
npm run lint                 # eslint
npm test                     # jest (jest-expo preset)
npm run api:types && git diff --exit-code src/api/schema.d.ts
npx expo export --platform android && npx expo export --platform ios
```

Format with `npm run format` (Prettier); CI doesn't check formatting.

Run one test file with `npx jest src/game/reducer.test.ts`, or one test with `npx jest -t "name of the test"`.

## API client

`api/openapi.json` is a copy of the server's spec. After copying a new version from the server, run `npm run api:types` to regenerate `src/api/schema.d.ts` and commit both. The scorekeeping read responses are bare objects in the spec, so changes to the entry context or the game list also need the zod schemas in `src/game/types.ts` and `src/api/http.ts`.

A change that needs new server support is made in the server repository first. The app probes for optional routes and keeps working without them; see [architecture](architecture.md#server-contract).

## Translations

Catalogs are in `src/i18n/locales/`, two per language: `<lang>.app.json` holds the app's own strings and `<lang>.terms.json` the shared terms. `npm run i18n:seed` rewrites the `fi`, `de` and `es` terms files from the server's `.po` files, read from a sibling checkout at `../ultiorganizer` (or a path given as an argument), and never touches the app files. Fix a wrong term in the server's `.po`, not here. A term the server has not translated falls back to English.

A new app string goes into all four `*.app.json` files. Tests check that every language has the same keys as English, with the same `{{placeholders}}`, and that no app key overlaps a term key. Within a language, a sentence that mentions a term uses the seeded word for it, and plurals use i18next's `_one`/`_other` suffixes.

The language choice is the `language` setting (`system` or a language code); `setLanguage` in `src/i18n/index.ts` applies it at startup and from Settings. The flags in `assets/images/flags/` are copied from the server's `images/flags/medium/`.

## Local Android build

EAS is the normal path. A local build is for when you want an APK on this machine, or an emulator.

Versions come from the repo: `node_modules/react-native/gradle/libs.versions.toml` (compileSdk 37, buildTools 37.0.0, NDK 27.1.12297006) and the Gradle wrapper (9.4.1). Gradle 9 runs on JDK 17 to 25; JDK 21 is known to work.

```sh
# SDK packages (sdkmanager from the command-line tools in $ANDROID_HOME/cmdline-tools/latest)
sdkmanager "platform-tools" "platforms;android-37.0" "build-tools;37.0.0" "ndk;27.1.12297006"
sdkmanager "emulator" "system-images;android-37.0;google_apis_playstore;x86_64"   # only for an emulator

export JAVA_HOME=/path/to/jdk-21 ANDROID_HOME=$HOME/Android/Sdk
APP_VARIANT=development npx expo prebuild --platform android   # generates android/
cd android && ./gradlew assembleDebug -Dorg.gradle.jvmargs="-Xmx4096m -XX:MaxMetaspaceSize=768m"
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

- The default Gradle heap (2 GB, from `android/gradle.properties`) can get the daemon killed on a machine with little memory. The `-D` flag overrides it for one build; `gradle.properties` is regenerated by prebuild.
- Prebuild rewrites the `android` and `ios` scripts in `package.json` to `expo run:*`. Revert that with `git checkout -- package.json` unless you want it.
- Emulator: needs `/dev/kvm` access (`test -w /dev/kvm`). Create an AVD with `avdmanager create avd -n ultiorg_api37 -k "system-images;android-37.0;google_apis_playstore;x86_64" -d pixel_8`, then start it headless with `emulator -avd ultiorg_api37 -no-window -no-audio -no-snapshot -gpu swiftshader_indirect`. Start it detached (`setsid nohup ... &`), or it dies when the launching shell exits. Install with `adb install -r <apk>`.
